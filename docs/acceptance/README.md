# 验收证据（入库副本）

`logs/` 整个目录在 `.gitignore:43` 里，现场日志不会进仓库。**对外可引用的证据一律以本目录为准**，
`logs/acceptance-a-*` 只是同一批文件的现场副本。

新增一批证据时注意两条忽略规则：`logs/`（整目录）和 `*.log`（所有扩展名）。`docs/acceptance/**/*.log` 已单独放行，
否则日志片段会被静默吞掉——第一批就踩过：目录 23 个文件、仓库也显示 23 个，看似对齐，其实是"少了 `a-block.log`、
多了本索引"撞了号。**核对要按目录列表逐个比，别只比数量。**

## 2026-11-09 · B 块补测：r2 学院层判据

目录 `2026-11-09/`，3 个文件。这一批只证明一件事：**总名额有余量时，超出的请求是被学院层
（不是 stock 层）拦下的**。第一轮 r2 用 `total=80`、`Σcollege=4×20=80`，两个数相等，
80 个成功先把 stock 打到 0，剩下 120 个在 `claim.lua` 的 stock 判定处就返回 2001，
**根本没走到学院判定**——"每院精确 20"是 80÷4 的算术结果，不能当并发证据。

| 文件 | 是什么 | 判据 |
|---|---|---|
| `r2-college-layer.md` | **先看这个**：为什么第一轮结论不成立、补测配置、三种码的分布、逐学院表、落库复核 | 全部 |
| `r2-burst-200-raw.csv` | 200 个请求的原始结果，**无表头**，每行 `学号,code`（`0`/`2002`/`2001`） | 逐请求 |
| `r2-roster-map.tsv` | `学号\t学院`，200 行。**没有它上面的逐学院表无法自查**——学院是按 `sid mod 4` 交错分配的，按学号每 50 个切块会得到 21/22/17/20 的假不均匀 | 归组 |

### 三个引用时必须注意的口径

1. **`total=200` 是临时抬上去的**，学院仍 `4×20=80`，故意留 120 缺口。跑完已
   `reset?resourceId=2&quota=80` 复位到基线（80/80、四院各 20、records 0、`balanced=true`）。
   引用时不要写成"r2 是 200 个名额的活动"。
2. **`2002` 的总数 120 = 200 − 80 是对的，但逐学院的 30 是 50 − 20**，两个减法不是一个来源；
   前者证明总量有富余，后者证明学院层精确。
3. **这批不证明吞吐**：`costMs=1033` 是 200 个请求打完的墙钟时间，含 200 线程建连，
   不是 QPS 口径，不能和 B1 的三条曲线比。

### 两个引用时必须注意的口径

1. **`a-block.log` 的行号指不到本仓库里的文件**。原始 `a3-final.log` 有 SQL 行且不入库，台账里"日志行 1527"这类引用
   只能靠 `a-block.log` 里保留下来的行号前缀核对。要完整复现就得重跑，不是翻仓库。
2. **这批证据证明的是"分支写对了"，不是"链路通了"**：`writeFinalReport` 的 `CLOSED` 是手工 `UPDATE` 造出来的，
   产品里没有任何代码会把活动置 `CLOSED`（R-7 因此定级 ⚠️，见 `README.md` §3.5「手工关账」）。
3. **10 秒不是生产值**：那是把 `--campusslot.reconcile.interval-ms` 压到 10000 的测试值，
   生产口径是"关账后 ≤1 个巡检周期（默认 5 分钟）出终版报表"。

### 采集环境

`slot-app` 8080（`college-quota-enabled=true`、`dev-endpoints=true`、巡检 `enabled=true interval-ms=10000`、
`logging.level.com.campusslot=INFO`）+ `slot-consumer` 8082；MySQL 127.0.0.1:3307、Redis 6379 均为 docker 容器。
注意 `INFO` 并**不能**关掉 SQL 日志（`StdOutImpl` 绕过 logback），所以证据日志是二次过滤后的；B1 压测必须用
`--spring.profiles.active=bench`，两者的数字不可比。
